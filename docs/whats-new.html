Changelog

What's new

Recent releases have made PigeonPost lighter on your mail server and harder to fool. A large mailbox now syncs in seconds over a single login; a provider outage is named as one and mail sent during it waits in the Outbox. Before that, meeting invitations and cancellations were tied to the people entitled to send them, a refused move stopped losing the message and a reopened draft kept its attachments. The newest release shows where a link really goes before you click it and turns emoticons into emoji; the one before redrew the compose icon.

v2.15.4

See where a link goes before you click it

  • Hovering a link shows its real destination in the tray at the foot of the window, with the site in bold, in the reader, a conversation, an attached email and compose
  • A link whose text names a different site is flagged in red; a site name spelt with lookalike letters shows in its raw xn-- form; a link PigeonPost will never open is labelled as one
  • Emoticons and shortcodes such as :) and :tada: show as emoji in mail you receive, while the stored message keeps what the sender wrote
  • They become emoji as you type a message, a template or a signature; Backspace straight afterwards puts the text back. Hovering any emoji names it
v2.15.3

A new compose icon

  • The pen on the compose button has been redrawn
v2.15.2

A rule's exceptions get a list of their own

  • Each condition in the rule editor carried a NOT button that read NOT whether it was on or off; only its colour told them apart, so a plain condition looked negated
  • The editor now shows a rule the way it runs: first what a message has to match, then under "Except when it matches any of these" the exceptions that let a message off
  • A button on each row moves it to the other list; each list has its own add button. Nothing about how rules run has changed and every saved rule opens exactly as it was
v2.15.1

A provider outage no longer asks you to check your password

  • When a mail server said the account was temporarily unavailable, PigeonPost sent you to check your address and password. The banner now says the problem is at the mail provider rather than with your account; mail is checked again automatically
  • A message, a server draft or a meeting reply sent during such an outage now waits in the Outbox and goes once the server is back, instead of failing. A reply saying the password itself needs changing is still reported straight away
v2.15.0

Large mailboxes sync in seconds with far fewer logins

  • A folder synced before is now refreshed from a short list of message numbers and flags; only new messages are downloaded in full. One account with 54 folders and about 47,000 messages never finished a sync before; it now syncs in about seven seconds
  • A full sync uses one login; between actions one connection per account is reused for up to five minutes. Against StartMail, which had blocked an address for too many logins, the busiest minute fell from 13 new connections to 3
  • Read marks, flags and tags waiting for the server go in one batch per folder and are cleared once confirmed, instead of piling up into thousands of logins
  • New-mail activity checks only the account that announced it; only an inbox that has grown counts as new mail
  • On an IMAP account a rule's mark read or flag now reaches the server and stays
  • Adding an account (or adding back one you removed) no longer announces the mail already in its inbox as new or lets your rules act on it
  • Failures that used to vanish are written to mail-errors.log; a new run.log records each sync step, holding no passwords or sign-in tokens
v2.14.0

Your calendar changes only for the right sender; a refused move keeps the message

  • A mailed cancellation now changes your calendar only when it comes from the meeting's organiser; a reply changes only its own attendee's answer. Anything else leaves the meeting in place with the message unread
  • Cancelling a series removes its moved occurrences too; cancelling one occurrence removes just that one
  • On a server without the MOVE command a refused copy no longer removes the message anyway. Where a server cannot remove only the chosen messages, PigeonPost refuses the move and says so
  • Permanent delete removes only the messages you chose
  • A recurring event with one moved occurrence survives import and sync instead of losing the rest of its series
  • Calendar files keep Outlook-style time zones, times with no zone, durations, reminders set from an event's end plus text in angle brackets. After the computer wakes, reminders for events already over are skipped
  • A mailbox the server renumbers is not taken as new mail, so a delete rule cannot reach the backlog
  • A queued message is sent exactly once; one the server accepted before the connection dropped counts as sent
  • A partly accepted move or delete reports what the server took and keeps its undo
  • Printing no longer fetches remote images you have not chosen to load
  • Contacts import Outlook's vCard 2.1 cards, skip and count a card with no name and read CSV files separated by semicolons or tabs
  • A compose holding only attachments asks before it is discarded; a rule's Now acts only on what its preview listed; a calendar server at an http:// address warns that the password travels unencrypted
v2.13.0

  • The Outbox shows the paperclip on a waiting message that carries files
  • Help > Guide now names everything PigeonPost fetches beyond your mail: the version check, remote images you choose to load and Microsoft sign-in
